# Phase 4 — UI Design Contract

> Visual and interaction contract for the **PLP Risk Studio dashboard** — a live React + Vite SPA streaming SVI surface updates from a Node.js event relay, with vault panels, what-if simulator, and dApp Kit deposit/withdraw flows. Audience: institutional LPs + Sui Overflow 2026 DeepBook-track judges. Tone: institutional-grade risk dashboard, not DeFi-degen UI. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (manual init in Phase 4 Wave 0) |
| Preset | `new-york` style + `slate` base color + CSS variables enabled |
| Component library | Radix Primitives (via shadcn wrappers) — `Card`, `Button`, `Badge`, `Tabs`, `Tooltip`, `Dialog`, `Slider`, `Input`, `Skeleton`, `Sheet`, `Toast` (Sonner), `Separator`, `Avatar`, `Progress` |
| Icon library | `lucide-react` (shadcn default; tree-shakeable, matches Radix density) |
| Font | `Inter` (variable) for UI + `JetBrains Mono` for numeric/digest fields. Loaded via `@fontsource-variable/inter` and `@fontsource/jetbrains-mono` (offline, no Google Fonts CDN — avoids privacy banner blockers on judges' browsers) |

**Initialization (Phase 4 Wave 0):**
```bash
cd dashboard && npx shadcn@latest init
# Style: new-york
# Base color: slate
# CSS variables: yes
# Path alias: @/* -> ./src/*
```

Components added on demand via `npx shadcn add card button badge tabs tooltip dialog slider input skeleton sheet sonner separator progress`.

**Rationale for shadcn:** institutional dashboard aesthetic without bespoke design tax; integrates with existing `dashboard/src/lib/*.ts` Phase 1 SVI evaluator files unchanged (shadcn touches `src/components/ui/` only). Plotly + Recharts render inside shadcn `<Card>` containers — no styling conflict because shadcn is utility-class + Radix, and Plotly/Recharts render to their own DOM trees.

## Spacing Scale

Declared values (multiples of 4; matches Tailwind default scale shadcn ships):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`space-1`) | Icon-to-label gaps, badge padding, slider tick marks |
| sm | 8px (`space-2`) | Compact element spacing inside cards, button icon gaps, table cell padding |
| md | 16px (`space-4`) | Default panel body padding, gap between form rows, Card content padding |
| lg | 24px (`space-6`) | Card-to-card gap inside a section, section heading bottom margin |
| xl | 32px (`space-8`) | Major section gap (Hero → Arb checker → Vault row), sticky header internal padding |
| 2xl | 48px (`space-12`) | Top-of-page hero margin (above 3D surface), modal vertical padding |
| 3xl | 64px (`space-16`) | Page-level top/bottom padding on `<main>` |

**Layout grid:** 12-column desktop, 1280px max-width container, 24px gutters. Mobile (≤768px): cards collapse to single column via CSS `@media`, no JS breakpoint logic.

**Touch-target exception:** `ConnectButton`, deposit/withdraw primary buttons, and slider thumbs are min `44×44px` (WCAG 2.1 AA) — implemented via `min-h-11 min-w-11` Tailwind classes on the underlying shadcn `<Button>`.

**Plotly 3D surface canvas:** fixed at `600px` height on desktop, `400px` on mobile. Recharts 2D panels: fixed at `320px` height inside Card body (gives the y-axis room and keeps the layout from jumping when data arrives).

## Typography

| Role | Size | Weight | Line Height | Family | Usage |
|------|------|--------|-------------|--------|-------|
| Body | 14px | 400 (regular) | 1.5 | Inter | Paragraph text, table cells, labels |
| Numeric | 14px | 500 (medium) | 1.4 | JetBrains Mono | Currency amounts, NAV, share counts, bps, percentages, tx digests |
| Heading | 18px | 600 (semibold) | 1.3 | Inter | Card titles ("Vault NAV", "Volatility Surface", "Open Hedges") |
| Display | 28px | 600 (semibold) | 1.2 | Inter | Sticky-header product name "PLP Risk Studio" + hero-section H1 only |

**Total declared sizes: 3** (14, 18, 28). **Total declared weights: 2** (400 + 600 in Inter; the 500 monospace is the single concession for tabular legibility — judges scanning a column of numbers need the medium weight to bind digits visually).

**Caps:** no all-caps labels (institutional dashboards use sentence case). One exception: status pills (`LIVE`, `RECONNECTING`, `STALE`) use uppercase 11px Inter at weight 600 with `tracking-wider`.

**Numeric formatting:** all on-chain u64 values are deserialized as `bigint` (per Phase 3 D-15 JSON convention), formatted via `Intl.NumberFormat` with the strategy_constants `NAV_SCALE` (10^9) and `DUSDC` 6-decimal divisors. JetBrains Mono tabular-nums (`font-feature-settings: "tnum"`) ensures column alignment.

Slate-based neutral palette from shadcn `new-york` preset. 60/30/10 split below assumes the `dark` theme (institutional dashboards default to dark; judges view in any lighting; reduces eye strain across the 3-min demo video). | Role | Value (dark) | Value (light) | Usage |

| Secondary (30%) | `slate-900` `#0f172a` | `white` `#ffffff` | Card backgrounds, sticky header, sheet/sidebar surface |
| Accent (10%) | `cyan-500` `#06b6d4` | `cyan-600` `#0891b2` | **Reserved-for list below — never used elsewhere** |
| Destructive | `rose-600` `#e11d48` | `rose-600` `#e11d48` | Withdraw confirmation button, "Cancel Redeem Request" button, stale-data red borders/pills |

**Accent reserved-for list** (explicit; never applied to all interactive elements):
1. Primary CTA button background ("Connect Wallet", "Deposit", "Confirm Deposit") — exactly one accent button visible per viewport
2. Active tab indicator underline (if tabs ship — currently single-page per D-06)
3. Active slider track fill (what-if simulator spot/vol sliders)
4. Live SVI surface plot's highest-density colormap band (Plotly `colorscale` top stop) — the SVI surface itself uses `Viridis` colormap but the LIVE pill on the sticky header is cyan to signal "real-time"
5. `LIVE` status pill on the sticky-header relay-status indicator
6. Hyperlinks in the README-style footer ("View source on GitHub", "Read the strategy whitepaper")

**Status semantics (institutional convention — locked):**

| Semantic | Token | Hex | Used For |
|----------|-------|-----|----------|
| Success / live | `emerald-500` | `#10b981` | Arb-checker GREEN status, "Deposit succeeded" toast, WebSocket connected pill |
| Warning / stale | `amber-500` | `#f59e0b` | Staleness pill at 30-60s threshold (yellow border on panel) |
| Danger / red-flag | `rose-600` | `#e11d48` | Staleness >60s, arb-checker RED status, relay-down pill, destructive button hover |
| Neutral info | `slate-400` | `#94a3b8` | Secondary text, captions, "last updated 3s ago" timestamps |

**Plotly colormap:** `Viridis` for the SVI surface (perceptually uniform, colorblind-friendly, foundation-grade convention). Arb-violation overlay markers in `rose-600`. `g(k)` plot line in `cyan-500` with a horizontal `rose-600` reference line at `y=0`.

**Recharts palette (vault panels):**
- Utilization gauge fill: `slate-500` baseline, `cyan-500` active band
- Token-bucket gauge: `emerald-500` full → `amber-500` <30% → `rose-600` empty
- Exposure bars (by oracle/strike/expiry): single-color `slate-400` bars; the chart's value is the shape, not chroma diversity
- PnL attribution stacked bar: PLP yield `emerald-500`, hedge cost `rose-600` (negative), hedge payoff `cyan-500`, net `slate-100`

**Critical: no rainbow vault dashboards.** Five colors max in any single panel. Color is data; decoration is gray.

## Copywriting Contract

All copy is **verb-first, plain English, institutional-tone**. No emoji, no exclamation points, no DeFi-degen language ("ape in", "moon", "gm"). Numbers spell out units ("0.50 DUSDC" not "0.5"). Tx digests truncated `0x1234…abcd` (8/4 ellipsis) with copy-on-click.

### Primary CTAs

| Element | Copy |
|---------|------|
| Header CTA (wallet disconnected) | `Connect wallet` |
| Header CTA (wallet connected) | Shows truncated address + `lucide-react` chevron, opens disconnect popover |
| Deposit primary button | `Deposit DUSDC` |
| Deposit confirmation button (in modal) | `Confirm deposit of {amount} DUSDC` |
| Redeem request button | `Request redemption` |
| Redeem fulfill button (after cooldown) | `Fulfill redemption` |
| Redeem cancel button | `Cancel request` |
| What-if simulator "reset" button | `Reset to current` |
| Arb-checker expand link | `View g(k) curve` |

### Empty states

| Element | Copy |
|---------|------|
| SurfacePanel (no oracle event yet) | Heading: `Waiting for first SVI update` / Body: `The relay is connected and listening. The first OracleSVIUpdated event will render the surface here.` |
| VaultPanel (vault not yet seeded) | Heading: `Vault is initializing` / Body: `Once the deployer seeds 10 DUSDC into the vault, NAV and share-price metrics will appear.` |
| BucketGauge (wallet disconnected) | Heading: `Connect wallet to view your withdrawal budget` / Body: `Each user has an independent token bucket that refills at 1.2 DUSDC per ms.` |
| PositionViewer (wallet connected, no positions) | Heading: `No positions yet` / Body: `Deposit DUSDC to mint vault shares and open your first hedged position.` |
| ExposurePanel (no open hedges) | Heading: `No hedges currently open` / Body: `Hedges are minted automatically on supply and rolled when within 48 hours of expiry.` |
| What-if simulator (no positions) | Heading: `Connect wallet to simulate` / Body: `Sliders shock your open hedges by spot ±5σ and vol ±2σ. PnL is recomputed in your browser.` |

### Error states

All error copy follows the template: `Problem: {what went wrong}. Next: {what the user does}.`

| Element | Copy |
|---------|------|
| Relay disconnected | `Relay disconnected. Reconnecting in {N}s.` (countdown updates every second) |
| WebSocket replay timeout | `Could not restore session state. Reload the page.` (with `Reload` button) |
| TESTNET-DEPLOY.json missing / status=pending_first_deploy | `Vault not yet deployed to testnet. The dashboard is in snapshot-only mode — live events resume after deploy.` |
| PTB sign failure (user rejected) | `Transaction rejected. No funds moved.` |
| PTB execution failure (on-chain abort) | `Deposit failed: {move_abort_code_message}. No funds moved.` |
| Insufficient DUSDC balance | `Insufficient DUSDC. You have {balance}; this deposit requires {amount}.` |
| Redemption cooldown not yet met | `Cooldown active. Fulfill available in {N} minutes.` |
| Oracle stale (>30s since last update) | Per-panel `amber-500` border + caption: `Last update {age} ago — data may be stale.` |
| Oracle very stale (>60s) | Per-panel `rose-600` border + caption: `Data stale — investigate before transacting.` |
| Arb-checker on stale surface | Status pill: `STALE — cannot verify` (gray, not green/red); body: `Arbitrage check requires SVI fresher than 5 minutes.` |

### Destructive actions

All destructive actions use **shadcn `<Dialog>` with explicit confirmation copy and a destructive-styled confirm button**. No browser `confirm()`.

| Action | Confirmation dialog |
|--------|---------------------|
| `Cancel request` (redeem) | Title: `Cancel redemption request?` / Body: `Your {shares} escrowed shares will be returned to your wallet. The 1-hour cooldown timer will reset if you submit a new request.` / Buttons: `Keep request` (default) + `Cancel request` (destructive) |
| `Fulfill redemption` (irreversible payout) | Title: `Fulfill redemption?` / Body: `You will receive approximately {payout} DUSDC and burn {shares} shares. This action cannot be undone.` / Buttons: `Back` (default) + `Fulfill redemption` (primary, not destructive — destructive is reserved for `Cancel`) |
| Disconnect wallet | No dialog (no on-chain effect) — single click on wallet badge → `Disconnect` menu item |

### Tone callouts (load-bearing)

- **Never** say "lossless", "guaranteed", "safe", "risk-free", or "best-in-class". Strategy whitepaper carries the marketing; dashboard is observational.
- **Always** show units. `0.50 DUSDC` not `0.5`. `1500 bps (15%)` not `15%` alone — bps is the canonical wire format and parenthetical aids non-specialists.
- **Timestamps** in dashboard rendered as relative ("3s ago", "2 minutes ago") with absolute UTC on hover. Implemented via `date-fns` `formatDistanceToNow` + `<Tooltip>`.

## Interaction Contracts (load-bearing for ui-checker)

### Staleness (per DASH-10, locked in CONTEXT.md D-05)

Per-panel state field tagged with `last_updated_ms` (relay heartbeat ts or event ts, whichever is fresher). Pill state machine:

| Age | Border | Pill | Caption |
|-----|--------|------|---------|
| 0–10s | none | `LIVE` (cyan) | `Last updated {N}s ago` |
| 10–30s | none | `LIVE` (cyan) | `Last updated {N}s ago` |
| 30–60s | `amber-500` 1px | `STALE` (amber) | `Last update {N}s ago — data may be stale` |
| ≥60s | `rose-600` 2px | `STALE` (rose) | `Data stale — investigate before transacting` |

Sticky-header global pill = worst-case across all panels. **Arb-checker special case:** if underlying surface is >5min old, status pill renders `STALE — cannot verify` (gray badge `variant="secondary"`) and body collapses to the caption only — no red/green claim on stale data (Pitfall 9 mitigation).

### WebSocket reconnect (per DASH-13, CONTEXT.md `Auto-reconnect strategy`)

Exponential backoff 1s → 2s → 4s → 8s → 16s → capped 30s. On reconnect: relay replay buffer fires first, snapshot store merged atomically, then live events resume. Visible behavior:

| State | Sticky-header pill | Body |
|-------|--------------------|------|
| Connected | `LIVE` (cyan) | All panels live; staleness rules apply |
| Reconnecting | `RECONNECTING in Ns` (amber) | Panels keep last-known state with stale borders applied; no white screen |
| Down ≥60s | `RELAY DOWN` (rose) | Inline alert above hero: "Relay disconnected. Last live data {age} ago. Live updates paused; on-chain state still readable via direct RPC." |

**Test gate:** kill the WS server mid-recording → verify no white screen, no infinite spinner, panels degrade gracefully with stale borders.

### What-if simulator (per DASH-09, CONTEXT.md D-09)

- Slider drag → `requestAnimationFrame`-throttled state update → `useMemo` recompute → Recharts re-render. Target <100ms end-to-end on mid-range laptop.
- Two sliders: `spot_shock_bps` in `[-50000, +50000]` (corresponds to ±5σ at bootstrap fallback 20% σ); `vol_shock_bps` in `[-4000, +4000]` (±2σ at 20% σ_θ).
- Reset button restores both sliders to 0; pressing `Esc` while focus is in the simulator card also resets.
- Bootstrap fallback per D-07 displays as caption under each slider: `±2σ ≈ ±20% (bootstrap fallback: <7d θ_T history)`.

### Deposit/Redeem flow (per DASH-11, CONTEXT.md D-11/D-12)

Standardized 3-step flow:

1. **Input** — amount, validation against wallet balance, real-time "You receive {Y} shares" preview computed client-side via `lib/svi.ts::binary_price` + share math
2. **Review** — `<Dialog>` shows: deposit amount, expected shares, hedge to be minted (strike + expiry + size), estimated gas. Confirm button = `Confirm deposit of {amount} DUSDC`
3. **Execute** — `signAndExecuteTransaction()`; Sonner toast `Submitting transaction...` → `Deposit succeeded` (with `<TxDigestLink>`) or error toast with retry button

Redeem flow extends with cooldown timer:

1. `Request redemption` → PTB → toast → state shifts to `Cooldown {59:59 → 0:00}`
2. Once cooldown elapses: `Fulfill redemption` button enables; `Cancel request` always enabled
3. Cancellation goes through destructive-confirmation Dialog per copywriting contract

### dApp Kit integration (per CONTEXT.md Claude's Discretion)

`<WalletProvider>` + `<SuiClientProvider>` at `src/main.tsx`. Network = testnet. AutoConnect on by default (Wallet Standard handles Slush/Suiet/Backpack). No custom wallet modal — `<ConnectButton />` is the single entry point. ConnectButton styling uses dapp-kit's default theme (do not override; consistency across Sui ecosystem aids judges' wallet detection).

## Plotly + Recharts Performance Contract

**Plotly `<SurfacePanel>`:**
- `useMemo` on `data` and `layout` props keyed by `(snapshot_hash, theme)`
- `revision` prop bumped on every snapshot update (forces internal redraw without prop-identity churn)
- WebGL renderer (`config={{ scrollZoom: false, displayModeBar: false }}` to lock down judges' interaction surface)
- 50×50 grid maximum; if relay sends a denser surface, downsample on client before render
- **Fallback path documented in CLAUDE.md:** if `react-plotly.js` wrapper proves problematic, swap to a 30-line custom hook calling `Plotly.newPlot()` directly. Test the wrapper in a per-push CI smoke test first.

**Recharts panels:**
- `ResponsiveContainer` with explicit aspect ratio (avoids the recharts ResponsiveContainer-infinite-loop bug when parent height is unset)
- `<XAxis>` / `<YAxis>` tick formatters use `Intl.NumberFormat` cached at module scope
- No more than 200 data points per chart for the v1 dashboard scope (exposure bars typically ≤10, g(k) curve = 200, PnL attribution = 4 bars)

## Accessibility Contract

- Every interactive element keyboard-reachable (shadcn primitives are Radix; this is free)
- Color is never the sole carrier of meaning — staleness has both color AND text caption; arb-checker has both color AND status text (`GREEN / RED / STALE`)
- All Plotly + Recharts panels include a `<CardDescription>` paragraph stating what the visualization shows in prose (for screen readers + judges scanning quickly)
- `aria-live="polite"` on toast region (Sonner default)
- WCAG AA color contrast: dark-mode text colors verified `slate-100` on `slate-950` = 16.7:1; light-mode `slate-900` on `slate-50` = 15.3:1
- Reduced-motion: SVI surface plot disables the `revision`-prop rotation animation when `prefers-reduced-motion: reduce` is set; data still updates
