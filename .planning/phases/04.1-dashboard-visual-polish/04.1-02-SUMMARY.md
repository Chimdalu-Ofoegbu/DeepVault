# Phase 04.1 Plan 02: Layout Shell Summary

Restructured the DeepVault dashboard from the Phase 4 flat single-column stack
into the handoff's `dash-body` rail + main shell — a new `Rail.tsx` grouped
scroll-anchor nav, a `Header.tsx` reskinned to the `db-bar` top bar, and an
`App.tsx` 3-row card grid with a headline `dh-stats` strip. The WebSocket data
spine and every panel prop are byte-identical to Phase 4; this is a pure
layout/composition move.

## What Was Built

**Task 1 — `Rail.tsx` (new).** A 232px `aside.rail` with the inline brand-mark
SVG + "DeepVault" wordmark, 4 grouped nav sections (Vault / Risk Studio /
Composability / Account), and a footer (`← Back to site` + network meta). The 13
rail items are resolved per the UI-SPEC Navigation Contract: 9 scroll-anchor
items call `scrollIntoView({ behavior: 'smooth' })` on a `[data-section]`
target (or `window.scrollTo` for the page-top Overview); 4 disabled items
(Drawdown replay, Single PTB, vUSDC share, Integrations) render with `--dim`
text, `cursor: default`, and a Radix `<Tooltip>` carrying the verbatim UI-SPEC
tooltip copy. An `IntersectionObserver` over the 6 observed `[data-section]`
elements tracks the active item (default = Overview/top). The footer network
meta reads the live testnet `vault_id` from `TESTNET-DEPLOY.json` (public
on-chain data) and renders `testnet · 0x2824…a911`.

**Task 2 — `Header.tsx` reskin to `db-bar`.** Replaced the 28px `<h1>PLP Risk
Studio</h1>` with a left breadcrumb (`DeepVault / Risk Studio / Overview`, using
the handoff `.crumb` + `<em>` separators). The right `db-bar-r` pill row folds
in `RelayStatusPill` (the `live · testnet` pill, `wsState` wiring intact) and
`GlobalStalenessPill`, plus a static `⌘K · Search` pill, a live UTC clock pill
(per-minute `setInterval` refresh), the `Deposit DUSDC` primary button
(`btn btn-primary sm`), and the dapp-kit `<ConnectButton>` wrapped in `db-avatar`
chrome. A commented theme-toggle slot is reserved for Plan 05. The
`data-testid="header-controls"` attribute and the `wsState`/`snapshot` prop
signature are preserved; a new optional `onDepositClick` prop was added.

**Task 3 — `App.tsx` restructure.** Replaced the `min-h-screen bg-slate-950`
wrapper + `max-w-[1280px]` vertical stack with the `dash-body` grid (`232px 1fr`
via the globals.css class). Left column = `<Rail />`; right column = `<main
className="dash">` holding the `<Header>`, the preserved relay reconnect/down
inline alert, the `db-headline` section, and the 3-row grid. The headline
renders the eyebrow kicker + `<h1>` (with the zero-hedge copy variant — "Vault
is live. Hedge engages on first deposit." — since the demo-open vault has zero
hedges) + the 4-cell `dh-stats` strip. The strip binds Net APY (`—`, awaiting
first cycle), Hedge ratio (`0.0%`, target band from `ALLOCATION_BPS`),
Utilization (real % from `utilizationBps`), and Vault NAV (`~$10` from
`total_assets`) directly from `useVaultState`/`useExposure` — VaultPanel is a
pure feeder and `<VaultPanel>` is NOT mounted. The 3-row grid: r1 = SVI surface
(`SurfacePanel` + `ArbCheckerPanel`) | `db-side` column (`BucketGauge` +
`ExposurePanel`), no Greeks card (LD-1); r2 = `PositionViewer` |
`WhatIfSimulator`; r3 = the static backtest link card | event-stream
placeholder. `DepositWithdrawPanel` sits below the grid keeping its
`data-section` anchor.

**Task 3b — Row-3 backtest link card.** A static `db-card pad` (no live data
binding, LD-3/LD-5): `db-mark` "§ Backtest" + `<h2>Backtest report</h2>`,
verbatim UI-SPEC body copy (`12-cycle replay · lookahead-audited. Full
institutional report renders drawdown, NAV, and premium-drag tables.`), an
awaiting-state note (`Report renders from the nightly backtest run.`), and the
verbatim `Open backtest report ↗` link pointing at `/reports/full-365d-report.html`.

### Note on Deposit-button wiring

The plan's Task 2 said to wire the `Deposit DUSDC` button to the
DepositWithdrawPanel deposit dialog, lifting shared open-state to App if the
panel controls its own. The panel DOES own its `dialogOpen` `useState` (Phase 4,
`DepositWithdrawPanel.tsx:181`), and the deposit dialog is a nested-component
internal — exposing it would require a non-trivial panel refactor (prop-drilling
controlled state through `DepositCard`). Per the no-regression mandate (this is
a layout plan), the chosen coordination is: `onDepositClick` scrolls smoothly to
the `[data-section="deposit-withdraw"]` panel so the user lands on the existing
3-step flow. The panel's deposit affordance is one click away and unmodified.
Documented as a decision rather than a deviation — both the plan's lift-state
and this scroll approach are explicitly offered as alternatives in the task body.
