# Phase 04.1 Plan 03: Panel Reskin Batch A Summary

Reskinned the two Risk Studio chart panels — SurfacePanel (3D SVI surface) and
ArbCheckerPanel (g(k) plot) — to the handoff `db-card` visual language, and
converted VaultPanel into a pure data feeder. Styling, markup, and chart-color
changes only; the Phase 4 data hooks, Plotly `useMemo`+`revision` perf logic,
`checkArb` compute, and `useVaultState` derivation are all intact.

## What Was Built

**Task 1 — SurfacePanel reskin (`SurfacePanel.tsx`).** Replaced the shadcn
`<Card>` chrome with the handoff `db-card svi-card` structure: a `db-h` header
(`db-mark` "§ Surface" + `<h2>SVI · live</h2>`) with a `db-tabs` row
("3D mesh" active; "Slice · τ=7d", "Slice · τ=14d", "replay ⏮" dim — visual-only
for v1). A `svi-params` strip below the header renders the live a/b/ρ/m/σ values
(dequantized from the `surface.svi` bigints at FLOAT_SCALING 1e9), `butterfly`
and `calendar` chips driven by `checkArb` (mint `.ok` when arb-free), and a
right-aligned live "Ns ago" mono-dim counter. At demo-open (no event) the strip
shows the UI-SPEC verbatim empty-state copy ("Waiting for surface data …").
A `db-foot` carries "Source · `OracleSVIUpdated` via predict-server.testnet" +
a real "live · revision N" counter. The Plotly surface keeps `type:'surface'`,
the `useMemo` grid/data/layout/config memoization, and the `revision`-prop
redraw logic UNCHANGED — only the colorway was recolored: `MINT_COLORSCALE` for
the surface `colorscale`, `CHART_COLORS.text2` for axis `color`,
`CHART_COLORS.gridLine` for `gridcolor`, and the Geist `CHART_FONT_FAMILY`.
No hardcoded `#94a3b8`/`#06b6d4` hex survives.

**Task 2 — ArbCheckerPanel reskin (`ArbCheckerPanel.tsx`).** Reskinned the
chrome to `db-card pad` with a `db-h` header (`db-mark` "§ Arb-free" + `<h3>`).
R-2 LOAD-BEARING KEEP honored: the dedicated g(k) 200-point Recharts
`<LineChart>` is RETAINED (DASH-05 / MATH-04 differentiator) — the handoff folds
arb status into the `svi-params` strip but the dropping of the g(k) plot would
regress a verified Phase 4 capability. The GREEN/RED/STALE status badge is a new
inline `StatusBadge` recolored to the handoff tokens (`CHART_COLORS.accent` mint,
`CHART_COLORS.hedge` coral, `CHART_COLORS.muted` for stale). The g(k) `<Line>`
stroke → `CHART_COLORS.accent`, the violation-threshold `<ReferenceLine y={0}>` →
`CHART_COLORS.hedge`, axis ticks/labels → `CHART_COLORS.text2`, tooltip →
`CHART_COLORS.cardBg`/`gridLine`. The `checkArb` `useMemo`, the 200-point gK
data, and the auto-expand-on-RED `<Collapsible>` logic are all unchanged. No
`#06b6d4`/`#e11d48`/`#10b981` hex survives.

**Task 3 — VaultPanel converted to a pure data feeder (`VaultPanel.tsx`).**
Per UI-SPEC #7 + Plan 04.1-02 (which mounts the headline `dh-stats` strip from
`vaultView` and does NOT mount a `<VaultPanel>` card), VaultPanel's card UI was
stripped unconditionally: the shadcn `<Card>` chrome, the local `Stat` helper,
and the Recharts `RadialBarChart` utilization gauge are all removed. The module
now renders no UI — it re-exports `useVaultState` / `VaultView` (one canonical
import surface for the headline strip + `DepositWithdrawPanel`) and exposes a
new pure `vaultStats(view)` selector that projects a `VaultView` into
display-ready figures (`navDusdc`, `utilizationPct`, `navPerShare`, `paused`).
`Number()` coercion is confined to that selector boundary; the BigInt math stays
in the untouched `useVaultState` hook. No chart hex literals survive.
