# Phase 04.1 Plan 04: Panel Reskin Batch B Summary

Reskinned the 5 Vault/Account panels (BucketGauge, ExposurePanel,
WhatIfSimulator, PositionViewer, DepositWithdrawPanel) and the 5 shared status
primitives to the handoff `db-card` visual language. Styling, markup, and
input-affordance changes only — every data hook (`useBucketState`,
`useExposure`, `usePositions`), the `whatIf.ts` client-side compute, and the
`@mysten/dapp-kit` PTB sign flow in DepositWithdrawPanel are preserved
byte-identical.

## What Was Built

**Task 1 — BucketGauge + ExposurePanel reskin.** BucketGauge moved from the
shadcn `<Card>` + Recharts RadialBarChart to the handoff `§ Withdrawals`
`db-card.pad` `bucket` layout: a 44px Geist Mono `bucket-num` showing the real
available % of NAV, a mint `bucket-bar` fill, and a `bucket-foot` carrying
`queue · 0` + the available/capacity DUSDC readout. The 3-state escalation
recolored from the Phase-4 emerald/amber/rose hex ternary to mint
(`CHART_COLORS.accent`) for a healthy bucket and coral (`CHART_COLORS.hedge`)
when the budget runs low. The 3-state wallet logic + `useBucketState` are
unchanged. ExposurePanel moved to the `§ Per-oracle` `db-card.pad` `oracles`
CSS bar-list — Recharts dropped entirely. BTC-only (LD-2): a single BTC oracle
row; the ETH/SOL/SUI rows are gone. Zero-exposure empty state renders the
UI-SPEC verbatim "BTC oracle · 0% exposure — no hedge legs open yet."

**Task 2 — WhatIfSimulator symmetric ±5σ 7-button shock-row (R-1).** The two
shadcn sliders are removed and replaced by a `shock-row` of 7 discrete
buttons. Per the PROJECT.md "±5σ BTC moves" scope lock the set is symmetric and
±5σ-bounded — `−5σ, −3σ, −2σ, flat, +2σ, +3σ, +5σ` — correcting the handoff's
asymmetric `−7σ … +5σ` (the −7σ step lies outside ±5σ). Clicking a button sets
it `.active` and feeds the corresponding σ multiplier into the EXISTING
`shockedPnL` / `whatIf.ts` compute, reused unchanged (only the input widget
changed from a continuous slider to one of 7 discrete σ steps). Output is the
handoff `shock-stats` grid + `shock-bar` loss-capped comparison bar, all bound
to the real `whatIf.ts` output over real hedges. The empty state keeps the
shock buttons visible and shows the UI-SPEC verbatim disabled-state copy.
Preview mode is preserved.

**Task 3 — PositionViewer BTC-only pos-table + DepositWithdrawPanel chrome.**
PositionViewer moved to the full-width `§ Positions` `db-card` with the handoff
`pos-table` (Geist Mono 12.5px cells, uppercase 10.5px `th`, `leg-dot` row
markers, status `chip`s). BTC-only (LD-2): the `All/BTC/…` asset-filter tabs
are dropped for a single disabled `BTC` indicator chip; every row's Underlying
is BTC. PnL columns recolored to mint/coral via the `pos-table` `td.pos`/
`td.neg` classes. `usePositions`, the zero-vs-unknown nullable invariant, and
the tooltips are intact. DepositWithdrawPanel got a CHROME RESKIN ONLY — the
shadcn `<Card>` wrapper replaced by `db-card`, buttons in the handoff `btn`/
`db-pill` language, withdraw-request + cancel confirm buttons coral, deposit
confirm mint. The withdraw-request gained a coral confirmation dialog carrying
the UI-SPEC §Destructive verbatim copy ("…A 1-hour cooldown applies before you
can claim."); the cancel dialog copy updated to the UI-SPEC verbatim text. The
3-step Input→Review→Execute flow, the `ptbBuilders.ts` builders, the pre-sign
balance check, the `useSignAndExecuteTransaction` signing path, and the Sonner
toasts are byte-identical (threat register T-04.1-10).

**Task 4 — 5 status primitives recolored.** StalenessPill and RelayStatusPill
moved from the Phase-4 cyan/amber/rose Tailwind ramp to the handoff mint/coral
OKLCH tokens (`var(--accent)` / `var(--hedge)`) applied via inline style; tone
is surfaced via a `data-tone` attribute (mint | coral). RelayStatusPill's
connected state gained the handoff `live-dot` element (the pulse keyframe
lands in Plan 06's motion pass). TxDigestLink's explorer link recolored to
mint, the copy button to `--muted`. GlobalStalenessPill inherits via
StalenessPill; NumericValue carries no color literals and is unchanged.
`useStaleness` / `WsState` logic intact.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] WhatIfSimulator −5σ button crashed the panel with EKOutOfRange**
- **Found during:** Task 2 (first `pnpm test` run of the reskinned panel)
- **Issue:** At the 20% bootstrap σ a −5σ step maps to a −100% spot move,
  which collapses the shocked forward to ~0. `binaryPrice` then computes a
  log-strike `k = ln(strike/forward)` that blows past its EKOutOfRange safe
  domain and throws — clicking the −5σ button blanked the whole panel.
- **Fix:** Clamp the spot move to `[−95%, +500%]` before deriving
  `spotShockBps`, so the shocked forward stays inside `binaryPrice`'s safe
  domain while −5σ remains the most extreme shock the user can apply (a −100%
  BTC move is also physically meaningless). Wrapped the per-hedge `shockedPnL`
  call in a try/catch as defense-in-depth — a pathological SVI surface now
  yields a zero-PnL row rather than crashing. The displayed shock % uses the
  clamped value so the readout matches the compute input.
- **Files modified:** `dashboard/src/components/panels/WhatIfSimulator.tsx`
- **Commit:** aa1874e (folded into the Task 2 commit)
