# Phase 04.1 Plan 05: Event Stream + Theme Toggle Summary

Built the two pieces of genuinely new functionality in the dashboard-reskin
phase: a live relay `EventStreamPanel` (D-03) and a working light/dark
`ThemeToggle` (D-02). Both reuse infrastructure that already exists — the
`useWebSocket` ring buffer and the `next-themes` provider — so no new data wire
and no new provider were built. Both were mounted into the Plan-02 layout shell:
the event panel into the row-3 placeholder, the toggle into the top-bar pill row.

## What Was Built

**Task 1 — `EventStreamPanel.tsx` (new).** The handoff `§ Stream` "Recent
events" card. It takes `{ events: RingEvent[] }` — App.tsx passes
`snapshot?.ring_buffer ?? []` — and is a pure consumer of the live ring buffer
that `useWebSocket.ts` `applyEvent` already keeps updated (100-cap). D-03's
"wire to the live WSS" requirement is satisfied by consuming the existing data
spine; no second WebSocket client was built. The card renders the `db-card`
`events` `pad` chrome with a `db-h` header (`§ Stream` `db-mark` +
`<h2>Recent events</h2>` + a mono dim `live-dot` + "WSS"), and a `ul.ev-list`
whose rows are the globals.css CSS grid `76px 80px 1fr` = timestamp /
`ev-k` type label / description. Event `name` strings are mapped heuristically
to the handoff short labels (SVI / supply / mint / rebalance / roll / withdraw);
`ev-k.acc` mint accent is applied to `rebalance` and `mint` events. The list is
sorted newest-first and capped at 14 rendered rows. The ticker prepend+highlight
behavior is implemented as React render state: the panel tracks the newest
`ts_ms`, and when a genuinely newer event arrives it flashes the newest `<li>`
with `background: color-mix(in oklab, var(--accent) 8%, transparent)` for 700ms
via a `setTimeout`, then clears it. The empty state (zero events — the real
testnet state until `make demo` runs) renders the UI-SPEC verbatim copy "No
events yet. Vault activity and OracleSVIUpdated events appear here in real
time." Security (threat T-04.1-13): every event string is rendered as plain
escaped React children; the component never opts out of React escaping and uses
no raw-HTML injection API, so a malicious relay payload cannot inject markup.

**Task 2 — `ThemeToggle.tsx` (new) + Header mount.** A small `db-pill`-styled
button for the top-bar pill row. It reuses the existing `next-themes`
`useTheme()` hook — `main.tsx` already wraps the app in
`<ThemeProvider attribute="class" defaultTheme="dark">`, so no new provider was
added; next-themes handles `localStorage` persistence and the pre-paint
flash-of-wrong-theme guard via its own sanitized inline script. Clicking the
pill calls `setTheme(isDark ? 'light' : 'dark')`. It shows a `☾ dark` /
`☀ paper` glyph+label. A hydration-mismatch guard renders a stable hidden
placeholder until `mounted` is true (next-themes' `theme` is undefined on the
first client paint). The toggle target values match the globals.css selectors
verified in Plan 04.1-01: `attribute="class"` toggles `.dark` / `.light` on
`<html>`; the dark token values live in `:root` + `.dark`, the paper override
under `.light`, so `setTheme('light')` activates the paper block. The control
is mounted into Header.tsx's reserved theme-toggle slot in the `db-bar-r` pill
row (the only Header.tsx edit). Security (threat T-04.1-14): no custom
pre-paint script, no dynamic-code-execution API — only `setTheme` with a
constrained `'light' | 'dark'` value.

**Task 3 — App.tsx row-3 mount.** Replaced the Plan-02 placeholder
`<div data-section-placeholder="event-stream" />` with
`<section data-section="event-stream"><EventStreamPanel events={snapshot?.ring_buffer ?? []} /></section>`
and added the import. The `snapshot` variable already existed in App.tsx from
the `useWebSocket` spine — the panel receives its slice exactly like every
other panel. No new hook or socket was added. The rail's History anchor remains
pointed at `[data-section="exposure"]` (unchanged from Plan 02, per the UI-SPEC
Navigation Contract) — the new `event-stream` section is the stable anchor for
the Event stream card itself, not the History target.
