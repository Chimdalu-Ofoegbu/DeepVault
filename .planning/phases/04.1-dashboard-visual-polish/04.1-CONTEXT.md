<domain>

<decisions>
## Implementation Decisions

### Reskin Strategy
- **D-01: In-place edit of the 8 existing panels.** Executors modify the existing components in `dashboard/src/components/{layout,panels,primitives,ui}/` directly — change styling/markup/tokens, keep all data wiring, hooks, and tests intact. The panels already pass Phase 4 verification; a parallel-rebuild-and-swap was rejected because re-wiring every data hook risks regressions in verified behavior. New file additions are allowed only for genuinely new UI (the event panel, theme-toggle control, shared style primitives).

### Theming
- **D-02: Wire a full light/dark theme toggle in 04.1.** Both token sets — the default dark canvas and the handoff's `[data-theme="paper"]` light override — are transcribed into CSS, AND a working toggle control ships in this phase (not deferred). The toggle is a real, persisted control, not just dead CSS. The user explicitly chose the fuller scope here over a dark-only-defer-toggle option.

### Event Stream Panel (new component)
- **D-03: Build `EventStreamPanel` and wire it to the live relay WebSocket stream.** The panel is new (no existing component renders relay events). 04.1 builds the styled panel AND connects it to the relay's live WSS feed so it shows real `OracleSVIUpdated` / supply / mint / rebalance / roll / withdraw events with the handoff's prepend+highlight ticker behavior. A visual-only stub with the wire deferred was rejected — the live event stream is a load-bearing "it's actually live" demo moment.

### Motion
- **D-04: Full motion pass, including the loader animation.** Everything in the handoff's motion language: the dashboard loader (animated SVI-draw), SVI mesh render, event-ticker prepend+highlight, shock-button active toggle, and hover/focus transitions on rail/cards/table rows. The user chose full motion over core-only or static-reskin. Motion must still "clarify, not decorate" per the Design Prompt — but the loader is in scope.

### Claude's Discretion
The following are builder calls — recorded for downstream agents, no user decision needed:

- **Geist font delivery:** Self-host/bundle the Geist + Geist Mono fonts (e.g. via `@fontsource` or local font files) rather than the Google Fonts CDN `<link>` the handoff prototype uses. Rationale: the dashboard is the demo *recording* target (Phase 0 D-14 — "no network surprises mid-take"); a CDN font is a recording-time risk. The visual output is identical.
- **Theme-toggle placement + persistence:** Toggle lives in the sticky top bar's `db-pill` row; theme choice persisted to `localStorage` and applied pre-paint to avoid a flash-of-wrong-theme. Default = dark.
- **Token mechanism:** Transcribe the handoff `:root` / `[data-theme="paper"]` OKLCH blocks into the dashboard's existing global CSS / shadcn token layer (the dashboard already runs shadcn — re-point token *values*, do not reinstall primitives). Per UI-SPEC researcher decision R-3.
- **Empty-state rendering:** Per UI-SPEC's empty-state contract — every panel renders an intentional zero/empty state (NAV ≈ 10 DUSDC seed, zero hedges, zero events) since that is the vault's real state at demo open, before `make demo` runs a live deposit+hedge.
- **Scope-vs-deadline note:** D-02 (full toggle) and D-04 (full motion incl. loader) expand 04.1 beyond a minimal reskin. This is a deliberate user choice ("quality over component count", PROJECT.md). The planner should still wave the work so a partial landing (tokens + panel reskins) is demo-usable even if toggle/loader polish slips.

</decisions>
