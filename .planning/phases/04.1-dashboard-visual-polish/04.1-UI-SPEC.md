# Phase 04.1 — UI Design Contract

> Visual and interaction contract for the DeepVault dashboard reskin. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase intent:** This is a *visual reskin*, not a greenfield build. The 8 React panels exist and work (Phase 4, 7/7 plans + verification). This contract maps the Claude Design handoff (`DeepVault-handoff/project/dashboard.{html,css,js}` + `styles.css`) onto the already-built `dashboard/src/` component tree. The reskin reproduces the handoff's visual output faithfully; only the 5 locked decisions below deviate from it.

## Locked Decisions (carried from orchestrator brief — do not re-litigate)

The user reviewed 5 scope conflicts between the handoff and PROJECT.md and chose **follow PROJECT.md, adapt the design**. These are baked into the contract below.

| # | Decision | Effect on contract |
|---|----------|--------------------|
| LD-1 | **Greeks panel DROPPED** | `§ Greeks / Net book` card removed. Row 1 side column = Token bucket + Per-oracle exposure only. Freed space rebalanced (see Layout Contract). |
| LD-2 | **BTC-only** | Positions table shows BTC legs only; exposure shows BTC oracle only. Asset-filter tabs (`All/BTC/ETH/SOL/SUI`) replaced with a single disabled `BTC` indicator. |

| LD-4 | **Single-page, scroll anchors** | Rail nav is kept visually (grouped Vault/Risk Studio/Composability/Account) but entries become in-page scroll anchors. Items with no on-page section are disabled with a tooltip. |
| LD-5 | **Real on-chain data, no mock numbers** | Every figure binds to a named real source. Every panel has an explicit empty state for the vault's actual demo-open state (NAV ≈ 10 DUSDC, zero hedges, zero events). |

## Spacing Scale

The handoff declares **4px base** (`styles.css` header comment). The dashboard's card/grid spacing must be multiples of 4. Values observed in `dashboard.css` and locked as the contract:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | inline gaps, chip padding-y, ri-dot offsets |
| sm | 8px | compact gaps (svi-params items use 18px — see exception), card-internal small gaps |
| md | 16px | header-to-body gaps inside cards (`db-h` margin-bottom 14–18px), top-bar padding |
| lg | 20px | **primary card padding** (`db-card.pad` = `20px 22px`); row gaps (`db-row gap: 20px`) |
| xl | 24px | rail padding, row vertical padding (`db-row padding: 24px 0`) |
| 2xl | 32px | headline vertical block, dash horizontal padding (`28px` — see exception) |
| 3xl | 64px | not used on dashboard (landing-page scale) |

**Exceptions (transcribed verbatim from the handoff — keep as-is for fidelity):**
- `db-card.pad` horizontal padding is **22px** (not 24), card header gaps 14/18px — handoff values; reproduce exactly.
- `.dash` horizontal padding is **28px**; `db-bar` negative-margins `-28px` to bleed the sticky bar full-width.
- `svi-params` item gap is **18px**; `db-tabs` gap **16px**; `dh-stat` padding `14px 22px`.
- These off-grid values are intentional handoff density choices. Fidelity to the handoff overrides strict 4-point adherence here; do not "correct" them.

Geist (sans) + Geist Mono. Two weight families in active use: **400 (regular)** and **500 (medium)**, plus **300 (light)** reserved for the one editorial accent (`hl-serif` headline span) and **600 (semibold)** for the brand wordmark. Headlines are weight 500, never 700.

| Stat value | Geist | 28px | 500 | 1.0 | `dh-v` headline stats; unit suffix `i` is 16px muted |
| Big numeric | Geist Mono | 44px | 400 | 1.0 | `bucket-num` (token-bucket % of NAV) |
| Body | Geist | 15px | 400 | 1.55 | `body` default; descriptive text |
| Table / data | Geist Mono | 12.5px | 400 | — | `pos-table`, `shock-stats`, `ev-list` |

## Color

60 / 30 / 10 split, verified against the handoff:

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (~60%) | `--bg` | `oklch(0.135 0.008 250)` | Page canvas, the `dash` background behind cards |
| Secondary (~30%) | `--bg-2` | `oklch(0.165 0.008 250)` | Every `db-card`, the rail (`bg-2`), headline stat cells, top-bar (blurred 80% bg) |
| Accent (~10%) | `--accent` (mint) | `oklch(0.88 0.18 155)` | See reserved list below |
| Destructive / hedge | `--hedge` (coral) | `oklch(0.70 0.18 28)` | See reserved list below |

**`--accent` (mint) is reserved for — explicit list, never "all interactive elements":**
- Primary CTA fill (`btn-primary` — "Deposit dUSDC" / "Deposit DUSDC")
- Positive PnL / positive trend values (`pos`, `dh-trend.pos`)
- "Healthy" / "in-band" / "ok" status (`chip.ok`, `svi-params .ok` butterfly/calendar)
- Active rail nav item left-dot + 10%-mix background tint
- Live-status dots (`live-dot`, `net-dot`) — the pulsing connection indicator
- Active `db-tabs em.on` underline (1px accent border-bottom)
- SVI surface mesh + front-curve stroke/gradient fill
- Token-bucket fill bar, oracle exposure bars, util bars
- Source-leg dot (`leg-dot.src` — the PLP supply row)
- Event-stream `ev-k.acc` accent labels (rebalance, mint)

**`--hedge` (coral) is reserved for — destructive + loss semantics only:**
- Negative PnL values (`neg`, table `td.neg`)
- Hedge-leg dot (`leg-dot` — OTM put binary rows)
- "rolling" / out-of-band warning chip (`chip.warn`)
- Active shock button (`shock.active` — 18% coral mix + coral border)
- Withdraw / redeem destructive affordances (see Copywriting → destructive)
- "RELAY DOWN" alert state
- Backtest "unhedged" comparison swatch / shock-bar `sb-bad`

Accent and hedge never appear together as decoration — coral always means "loss/hedge/destructive," mint always means "yield/healthy/positive." This semantic split is load-bearing for the product story and must not be diluted.

## Decisions Made by Researcher (recorded per orchestrator instruction)

Where the handoff left something the 5 locked decisions did not resolve, the call was made to best honor PROJECT.md + the handoff style:

| ID | Decision | Rationale |
|----|----------|-----------|
| R-1 | What-if input affordance = 7 discrete shock buttons (handoff), not the Phase 4 dual sliders | The handoff `shock-row` is the canonical visual; PROJECT.md's "±5σ" requirement is satisfiable with discrete −7σ…+5σ steps. The client-side `whatIf.ts` compute is reused; only the input widget changes. Keeps fidelity to the handoff. |
| R-2 | Arb-checker g(k) plot panel is RETAINED inside/below the SVI card, even though the handoff folds arb status into the `svi-params` strip | DASH-05 / MATH-04 make the visible g(k) array a load-bearing differentiator ("most teams ship a boolean; we ship the array"). Dropping it to match the handoff would regress a required Phase 4 capability. The `svi-params` `butterfly·ok`/`calendar·ok` chips are the at-a-glance status; the g(k) plot stays as the detail. |
| R-3 | Token mechanism = re-point shadcn semantic aliases at OKLCH values rather than rip out shadcn | Lowest-risk path to the reskin: existing Radix/shadcn primitives keep working, the new OKLCH `:root` + handoff-named tokens drive the visual change. Avoids re-installing 13 components. |
| R-4 | "Backtest report" card may show a static sparkline only if sourced from the committed Phase 3 report JSON; otherwise text-only | Honors LD-3 (no live widget) and LD-5 (no fictional data) — a sparkline drawn from real committed backtest output is real data; an invented one is not. |
| R-5 | Headline copy has a zero-hedge variant (`Vault is live. Hedge engages on first deposit.`) | LD-5 demands the design look intentional at demo-open. The handoff's "Hedge is in position" is false when 0 hedges exist; the variant keeps the headline truthful. |
| R-6 | Casing normalized to `DUSDC` (handoff writes `dUSDC`) | Matches the on-chain `DUSDC` type tag and existing `DepositWithdrawPanel` copy; avoids a casing inconsistency between the reskin and the live PTB flow. |
