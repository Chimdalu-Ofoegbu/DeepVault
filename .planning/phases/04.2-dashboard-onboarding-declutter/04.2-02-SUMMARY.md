# Phase 04.2 Plan 02: Rail + Header Declutter Summary

**Decluttered the 13-item/4-group nav rail to 6 live mode-coupled items in 2 groups with a mode-keyed IntersectionObserver (event-stream observed, exposure dropped), removed the dead command-palette header pill, made the breadcrumb mode-aware, and re-pointed two fragile positional responsive CSS rules onto a stable .db-clock class — a reorganization with the data spine and every kept control byte-identical (LD-3).**

## Accomplishments

- **Rail: 13 items / 4 groups -> 6 live items / 2 groups.** The 4 disabled tooltip stubs (Drawdown replay, Single PTB, vUSDC share, Integrations) and the 3 duplicate-anchor items (Hedge ladder, History, Reports) are gone; the Composability and Account groups dissolved (LD-6). The disabled-item kind is retired entirely — `DisabledItem`, the `TIP_*` constants, all `Tooltip*` imports, and the `TooltipProvider` wrapper are removed (zero Tooltip references remain in the file).
- **Mode-coupled rail (OQ-3).** Each nav item carries a `mode`. A cross-mode click calls `setMode(item.mode)` first, then defers `scrollToSection(item.section)` one frame via `requestAnimationFrame` so the target anchor (which only mounts after the mode switch) is present — the scroll always lands, never no-ops. Same-mode clicks scroll directly.
- **Mode-keyed observer reconciled (D-2 / R-4).** `OBSERVED_BY_MODE` is `{ vault: [deposit-withdraw, position-viewer], risk: [hero, what-if, backtest, event-stream] }`. `event-stream` is now observed (the D-2 drift fix — Plan 01 made it the real Risk r2 anchor), and the stale `exposure` rail/observer mapping is dropped. The observer effect re-runs on `[mode]` so it rebinds when the prior mode's anchors unmount. Active state is mode-gated (`item.mode === mode`).
- **Header decluttered (LD-7, R-3, D-3).** The dead command-palette search pill (no handler, `tabIndex={-1}`) is deleted; the UTC clock carries a stable `db-clock` class; the breadcrumb middle crumb is mode-aware (`Vault` / `Risk Studio`). All six surviving controls remain verbatim: RelayStatusPill, GlobalStalenessPill, UTC clock, ThemeToggle, the Deposit DUSDC CTA, and the wallet ConnectButton.
- **Responsive CSS re-pointed (D-3).** The `<=1200px` rule now hides `.db-bar .db-clock` (was `.db-pill:nth-child(3)`), and the dead `<=1024px .db-pill.mono:first-of-type` rule was removed with its whole media block. Deleting the search pill no longer shifts which pill a `display:none` rule targets. Plan 01's `.db-mode` toggle CSS is intact.
- **Build gate green.** `tsc --noEmit` exit 0; production `vite build` exit 0 (`✓ built in 2m 24s`); `vitest run` **427/427 passed (20/20 files)** — zero regression, no test assertions required updating.

## Decisions Made

- **Observer-only event-stream reconciliation (no 7th rail item).** The UI-SPEC allowed an optional `Activity -> event-stream` rail item. I kept the rail at exactly 6 items (CONTEXT "~6" target) and satisfied D-2/R-4 in the OBSERVER (`OBSERVED_BY_MODE.risk` includes `event-stream`) rather than adding a nav entry. The observer reaching `event-stream` is what R-4 requires; a rail item is not.
- **`<=1024px` media block removed entirely** (not retained empty, not re-pointed onto `.db-clock`). Its only rule hid the now-deleted search pill and is fully redundant with the wider `<=1200px` `.db-clock` hide. Re-pointing it would have created a second, redundant clock-hide; retaining it empty would be dead CSS.
- **`handleDepositClick` left unchanged.** Confirmed against Plan 01 SUMMARY + the live App.tsx:82-90 that it already calls `setMode('vault')` then defers the scroll one frame (Anchor Integrity rule 3). No edit needed; no duplication added.
- **`setMode: (m: Mode) => void` prop type** on both Rail and RailGroup — assignable from React's `Dispatch<SetStateAction<Mode>>`, so App passes its `setMode` directly without leaf components importing React dispatch types.
