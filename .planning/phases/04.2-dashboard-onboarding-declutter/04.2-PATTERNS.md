## CRITICAL DISCREPANCIES vs CONTEXT.md / UI-SPEC (planner MUST read)

Three places where the live codebase contradicts the upstream current-state evidence. None block the phase, but the planner must plan around them or the reorg will introduce DOM bugs.

### D-1 — Duplicate `[data-section]` anchors (panel root AND App wrapper)

CONTEXT.md lists the "real unique `[data-section]` targets" as a flat set. In reality **three anchors are rendered TWICE** — once on the panel's own root `db-card`, and again on the `<section>` wrapper App.tsx puts around it:

| Anchor | App.tsx wrapper | Panel-internal duplicate |
|--------|-----------------|--------------------------|
| `position-viewer` | `App.tsx:214` `<section data-section="position-viewer">` | `PositionViewer.tsx:101,119,138,161` (every return path, `<div className="db-card positions" data-section="position-viewer">`) |
| `exposure` | `App.tsx:206` `<section data-section="exposure">` | `ExposurePanel.tsx:41` (`<div className="db-card pad" data-section="exposure">`) |
| `deposit-withdraw` | `App.tsx:272` `<section data-section="deposit-withdraw" …>` | `DepositWithdrawPanel.tsx:93,111,127` (every return path) |

`querySelector('[data-section="X"]')` returns the **first match in document order** — today that is always the App wrapper (it encloses the panel). The IntersectionObserver `observer.observe(el)` (Rail.tsx:141-144) also only ever grabs the first match. So duplicates are currently harmless. **But** when the Vault view re-mounts `PositionViewer`/`DepositWithdrawPanel` in a new position, the planner must NOT add a *third* wrapper, and if `PositionViewer` ends up mounted in BOTH modes (UI-SPEC R-2 path b), there will be two live `position-viewer` anchors in different scroll positions → the rail/observer will bind to whichever renders first. **Recommendation for the planner:** pick UI-SPEC R-2 path (a) (do not dual-mount PositionViewer) to avoid two `position-viewer` anchors; OR if dual-mounting, drop the App-level wrapper and rely on the panel-internal `data-section` so there is exactly one per mode. LD-3 says props are byte-identical — note the panel-internal `data-section` is a *panel internal*, so removing the App wrapper (not the panel attr) is the LD-3-safe lever.

### D-2 — `event-stream` observer drift is real and exactly as R-4 describes

Confirmed: `App.tsx:265` renders `<section data-section="event-stream">`, but `Rail.tsx:90-97` `OBSERVED_SECTIONS` does **not** include `event-stream` — it includes `exposure` instead, and the "History" rail item (Rail.tsx:60) points at `exposure`. So the EventStream section is never observed and is unreachable from the rail. UI-SPEC R-4 mandates reconciling this. The planner's new `OBSERVED_SECTIONS` must be derived from the actually-mounted anchors per mode (see § Pattern Assignments → Rail.tsx).

### D-3 — Header responsive selectors target the SEARCH pill, not the clock (UI-SPEC § Header Declutter is slightly wrong)

UI-SPEC LD-7 says "the `≤1200px` rule hid the clock as `db-pill:nth-child(3)`." **That is incorrect against the live DOM.** Verified child order of `.db-bar-r` (Header.tsx:64-93):

| DOM child # | Element | Class | `.db-pill`? | `.db-pill.mono`? |
|-------------|---------|-------|-------------|------------------|
| 1 | RelayStatusPill | `<Badge>` (`inline-flex … border`) | no | no |
| 2 | GlobalStalenessPill → StalenessPill | `<span class="inline-flex …">` | no | no |
| 3 | **Search pill** | `db-pill mono` | yes | yes (1st) |
| 4 | UTC clock | `db-pill mono` | yes | yes (2nd) |
| 5 | ThemeToggle | `db-pill mono` | yes | yes (3rd) |
| 6 | Deposit DUSDC | `btn btn-primary sm` | no | no |
| 7 | ConnectButton | `db-avatar` wrapper | no | no |

- `globals.css:912` `.db-bar .db-pill:nth-child(3)` → the element that is BOTH a `.db-pill` and the 3rd child = the **search pill** (not the clock).
- `globals.css:917` `.db-bar .db-pill.mono:first-of-type` → the **search pill** again.

So **both** responsive hides currently target the search pill. When LD-7 deletes the search pill, child indices shift: the clock becomes `nth-child(3)` and the FIRST `.db-pill.mono`. Net effect of a naive deletion: the `≤1200px` rule starts hiding the clock (probably the originally-intended behavior) and the `≤1024px` rule also starts hiding the clock. The planner must **explicitly re-point both selectors to a stable hook** (e.g. give the clock pill a dedicated class like `db-clock` and rewrite the two media-query rules to target it) rather than rely on `nth-child`/`first-of-type`, exactly as UI-SPEC LD-7's parenthetical ultimately instructs. Do NOT leave the `nth-child(3)` / `first-of-type` selectors as-is after deletion.

### Mode toggle — analog: `DepositWithdrawPanel.tsx` + `ui/tabs.tsx`

**The installed Radix `Tabs` primitive EXISTS** at `dashboard/src/components/ui/tabs.tsx` (shadcn new-york, verbatim `@radix-ui/react-tabs` wrapper). Confirmed it is the ONLY `Tabs` usage in the repo — `DepositWithdrawPanel.tsx` is the sole consumer, used for the Deposit/Redeem in-card tabs. UI-SPEC R-1 (build the mode toggle on Radix `Tabs`, NOT on `.db-tabs em` and NOT a hand-rolled `<button>` pair) is satisfiable with zero new installs.

**Existing `Tabs` usage to copy the wiring shape from** (`DepositWithdrawPanel.tsx:53,135-157`):

```tsx
import { Tabs, TabsContent, TabsList, TabsTrigger } from '@/components/ui/tabs';
// …
<Tabs defaultValue="deposit">
  <TabsList>
    <TabsTrigger value="deposit">Deposit</TabsTrigger>
    <TabsTrigger value="redeem">Redeem</TabsTrigger>
  </TabsList>
  <TabsContent value="deposit"> … </TabsContent>
  <TabsContent value="redeem"> … </TabsContent>
</Tabs>
```

**KEY DELTA for the mode toggle (per UI-SPEC § Mode Toggle → Mounting):** the DepositWithdraw usage is *uncontrolled* (`defaultValue`) and mounts BOTH `TabsContent` panels. The mode toggle must be **controlled** (`value={mode} onValueChange={setMode}`) and must **NOT** render the heavy Vault/Risk subtrees inside `TabsContent` — instead use the `Tabs`/`TabsList`/`TabsTrigger` for the *control chrome + a11y* only, and render the content via a sibling conditional (`{mode === 'vault' ? <VaultView/> : <RiskView/>}`) so the inactive mode is unmounted (avoids running two Plotly/surface trees). Pattern:

```tsx
// In App.tsx, controlled, content rendered as siblings (NOT inside TabsContent):
<Tabs value={mode} onValueChange={(v) => setMode(v as 'vault' | 'risk')}>
  <TabsList aria-label="Dashboard view mode" className="…segmented override…">
    <TabsTrigger value="vault">Vault</TabsTrigger>
    <TabsTrigger value="risk">Risk Studio</TabsTrigger>
  </TabsList>
</Tabs>
{mode === 'vault' ? (/* Vault subtree */) : (/* Risk subtree */)}
```

**Styling delta (UI-SPEC § Mode Toggle → Visual treatment):** `ui/tabs.tsx` ships **Tailwind utility classes against shadcn semantic tokens** (`bg-muted`, `data-[state=active]:bg-background`, `text-muted-foreground`, `ring-ring`), NOT the OKLCH `db-*` tokens. The semantic aliases were re-pointed to OKLCH in 04.1 (UI-SPEC R-3), so the default rendering already inherits the palette — but the UI-SPEC wants a *specific* segmented look (`var(--bg-2)` track, `3px` padding, mint `color-mix(accent 12%)` active bg, mono 12.5px). The planner should pass a `className` override to `TabsList`/`TabsTrigger` (the primitive's `cn(...)` merges it) or add a small CSS class — do NOT edit `ui/tabs.tsx` itself (it is a regen-able shadcn primitive). The Radix `:focus-visible` ring is already wired (`focus-visible:ring-2 focus-visible:ring-ring` at `tabs.tsx:39`); `--ring` = mint, so the focus contract is met for free.

**Accessibility (UI-SPEC hard requirement, all Radix-provided):** `role="tablist"`/`role="tab"`, `aria-selected`, ←/→/Home/End roving focus, `activationMode="automatic"` default — all ship with `TabsPrimitive`. Just add `aria-label="Dashboard view mode"` to `TabsList`.

## Shared Patterns

### Pattern A — Reuse the active-nav accent idiom for the active toggle tab

**Source:** `globals.css:222-228`
**Apply to:** the mode toggle's active `TabsTrigger` (UI-SPEC: active = `color-mix(accent 12%)` bg + `--text` label — the SAME family as the active rail item, an explicitly-listed accent reservation).

```css
.rail-nav a.active {
  background: color-mix(in oklab, var(--accent) 10%, transparent);
  color: var(--text);
}
.rail-nav a.active .ri-dot { background: var(--accent); }
```

Coral (`--hedge`) MUST NOT appear on the toggle.

### Pattern B — `.db-tabs em` is the SVI in-card switcher; do NOT reuse it for the mode toggle

**Source:** `globals.css:475-495` + live usage `SurfacePanel.tsx:203-208` (`<div className="db-tabs"><em className="on">3D mesh</em> …`).
**Why it matters:** UI-SPEC R-1 explicitly forbids reusing `.db-tabs em` for the mode toggle — it is decorative `<em>` styling with **no ARIA** (`role`, `aria-selected`, roving focus all absent) and is reserved for the SVI 3D-mesh / slice switch inside `SurfacePanel`. The mode toggle uses Radix `Tabs` (Pattern, above) precisely to get the a11y `.db-tabs` lacks. Listed here so the planner does not accidentally pick the visually-similar wrong primitive.

### Pattern C — `.db-pill` chrome (for sizing kinship, not the toggle track)

**Source:** `globals.css:308-328`. The toggle triggers borrow the `7px 16px`-ish padding idiom and mono 12.5px from `.db-pill` / `.btn.sm`; the TRACK uses `var(--bg-2)` per UI-SPEC, not `.db-pill`'s transparent bg. Reference only.

### Pattern D — Theme/persistence boundary (do NOT add persistence to mode)

**Source:** `ThemeToggle.tsx:1-19,57-58`. ThemeToggle uses `next-themes` `localStorage` persistence — this is **unrelated** to the mode toggle. LD-2 mandates `mode` is in-memory React state ONLY (no `localStorage`, no URL, refresh returns to Vault). Do not copy the persistence pattern onto `mode`.
