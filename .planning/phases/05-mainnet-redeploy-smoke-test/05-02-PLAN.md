## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → Sui mainnet RPC | Ubuntu runner makes curl requests; no secrets transmitted, output is markdown report |
| GitHub Actions runner → GitHub Issues API | Uses GITHUB_TOKEN automatic auth + `permissions: issues: write`; minimum-scope authority |
| Repo variable PREDICT_MAINNET_CANDIDATE → workflow | Set by human via gh CLI or web UI; only readable by workflow code, never logged in plaintext outputs (no secret data, but identity-bound) |
| Markdown report → GitHub Issue body | Issue is public on the repo; report contains package_id + RPC output, no secrets |

## STRIDE Threat Register (ASVS L1)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | S (Spoofing) | Workflow trigger from fork PR | mitigate | Scheduled workflows do not fire on fork PRs (GitHub policy); workflow_dispatch requires repo write permission. RESEARCH §"Cron mechanics" caveat 4 — N/A for solo build. |
| T-05-02-02 | T (Tampering) | scripts/predict-mainnet-check.sh modifies config/mainnet.toml | mitigate | Task 1 acceptance criteria includes `! grep -q 'sed -i' scripts/predict-mainnet-check.sh` and `! grep -q 'config/mainnet.toml' (in modification context)` — script is read-only; human commits the flip per D-04. |
| T-05-02-03 | R (Repudiation) | Verdict provenance | mitigate | The GitHub Issue is the permanent audit trail (D-04). Issue body includes ${NOW_ISO} timestamp + raw VERDICT_JSON; the human's config-flip commit references the Issue # in the commit message (RESEARCH §"Required human action"). |
| T-05-02-04 | I (Information disclosure) | GITHUB_TOKEN leakage in workflow logs | mitigate | `permissions:` block restricts token to `issues: write + contents: read` (minimum scope per RESEARCH §"Cron mechanics" caveat 3). peter-evans/create-issue-from-file@v6 uses the auto-injected token; no manual secret handling. |
| T-05-02-05 | D (DoS) | Spurious shipped:true verdict if Mysten reuses a stale package id | mitigate | ABI-match check catches structural drift (added/removed functions). If ABI_MATCH=false, verdict markdown HALTS human (RESEARCH §"Verdict for Phase 5 plan"). |
| T-05-02-06 | E (Elevation of privilege) | False shipped:true with structurally-changed ABI poisoning MAINNET-DEPLOY.json | mitigate | Two-layer defense: (a) ABI_MATCH=false flag in Issue; (b) Plan 05-01 preflight Step 14 verifies Move.toml [addresses].predict matches config/mainnet.toml [predict].package_id — the human must align both, which forces a code review of the predict_adapter integration. |
| T-05-02-07 | T (Tampering) | RPC response forgery via DNS spoofing | accept | curl uses HTTPS with cert validation by default (-fsS); attacker would need to compromise the runner's CA store. ASVS L1 baseline acceptance for public-data probe. |
| T-05-02-08 | I (Information disclosure) | curl error output reveals internal RPC endpoint behavior | accept | `https://fullnode.mainnet.sui.io:443` is public; no internal infrastructure exposed. |

**High-severity threats:** T-05-02-06 (mitigated via two-layer defense). All other threats mitigated or accepted with rationale.
