## Recovery (operator runbook)

### Split-demo path: restoring allocation_bps after a failed restore step

The Plan 05-04 smoke test `runSplitDemoPath` runs the D-05 fallback ON MAINNET when
`predict_mainnet_shipped=false`. The procedure is:

1. AdminCap: `admin_tune_strategy(allocation_bps = 0)`  ← BEFORE supply
2. `vault::supply` (no hedge mint because allocation=0)
3. `redeem_request` → wait cooldown → `redeem_fulfill`
4. AdminCap: `admin_tune_strategy(allocation_bps = <prior>)`  ← AFTER fulfill (RESTORE)

If step 4 fails (RPC error, gas exhaustion, etc.) the vault is LEFT with
`allocation_bps = 0` — future supply transactions will not buy hedges. This is the
manual recovery procedure to restore the prior value (typically 1000 bps = 10%
per shared/strategy.toml [hedge_policy].allocation_bps).

**Prior value:** Read from `STRATEGY_CONSTANTS.ALLOCATION_BPS` in
`dashboard/src/lib/strategy_constants.ts`, or directly from
`shared/strategy.toml` `[hedge_policy].allocation_bps`. Default is **1000** (10%).

**CLI invocation (mainnet, SUI_CONFIG_DIR-scoped per Phase 0 D-06):**

```bash
# Verify you are on mainnet and SUI_CONFIG_DIR is correctly scoped
export SUI_CONFIG_DIR=~/.sui/sui_config_mainnet
sui client active-env   # must print: mainnet
sui client active-address   # must print the deployer address that holds AdminCap

# Read the values from MAINNET-DEPLOY.json
PACKAGE_ID="$(jq -r '.package_id' .planning/phases/05-mainnet-redeploy-smoke-test/MAINNET-DEPLOY.json)"
VAULT_ID="$(jq -r '.vault_id' .planning/phases/05-mainnet-redeploy-smoke-test/MAINNET-DEPLOY.json)"
ADMIN_CAP_ID="$(jq -r '.admin_cap_id' .planning/phases/05-mainnet-redeploy-smoke-test/MAINNET-DEPLOY.json)"
QUOTE_TYPE="$(jq -r '.quote_type_tag' .planning/phases/05-mainnet-redeploy-smoke-test/MAINNET-DEPLOY.json)"

# Restore allocation_bps to 1000 (10%). Adjust the literal if shared/strategy.toml has changed.
PRIOR_ALLOCATION_BPS=1000

sui client call \
    --package "${PACKAGE_ID}" \
    --module vault \
    --function admin_tune_strategy \
    --type-args "${QUOTE_TYPE}" \
    --args "${ADMIN_CAP_ID}" "${VAULT_ID}" "${PRIOR_ALLOCATION_BPS}" \
    --gas-budget 200000000
```

**Verification after restore:**

```bash
# Read the vault shared object content and confirm allocation_bps == 1000
sui client object "${VAULT_ID}" --json \
  | jq '.data.content.fields.strategy.fields.allocation_bps // .data.content.fields'
```

The exact field path depends on `contracts/sources/vault.move` layout; if the
above jq path returns null, expand the `.data.content.fields` block and locate
the allocation_bps value manually. After restore, future supply transactions
will resume buying hedges per the configured policy.

### Other recovery procedures (carried forward from prior Phase 5 notes)

- **redeem_request succeeded but redeem_fulfill failed:** Run `redeem_cancel<USDSUI>(vault, ctx)` to return escrowed Coin<SHARE> to the requester wallet (timestamp untouched per `contracts/sources/redeem.move:201-220`). Retry redeem_fulfill after liquidity recovers.
- **NAV gate failed (drift > 10 bps):** Pause the vault via `admin_pause` (AdminCap-gated) and investigate accounting drift before any further activity. AdminCap pause halts supply but NOT redeem (per CONTEXT.md D-10) — existing depositors can still exit.
- **Gas exhaustion mid-cycle:** Top up to $150 total per existing budget Risk Flag; resume smoke test from the last successful checkpoint.
```
