<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → mainnet RPC | predict-mainnet-check.sh issues a curl to `https://fullnode.mainnet.sui.io:443` — TLS endpoint owned by Mysten; we only read |
| operator shell → mainnet keystore | preflight.sh reads `$SUI_CONFIG_DIR` and `sui client gas / objects --json` — keystore is local; only reads, no signing |
| committed script → future operator | preflight.sh is the document the post-submission operator trusts to gate `sui client publish` — its assertions ARE the safety perimeter |
| config/mainnet.toml → preflight assertions | preflight asserts state of config; future TBD-leak (e.g. testnet DUSDC tag accidentally pasted into mainnet config) is caught here |

## STRIDE Threat Register (ASVS L1 coverage)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Spoofing | scripts/predict-mainnet-check.sh trusts the mainnet RPC's `sui_getObject` response | accept | TLS endpoint owned by Mysten; we read public on-chain data. Same trust profile as every other RPC call in the project. Bounded blast radius: a spoofed `shipped:true` only causes an erroneous proceed signal — preflight has 13 other gates that would still catch downstream issues. |
| T-05-02 | Tampering | preflight.sh's TBD-slot scan misses a TBD because of header prose containing the string `"TBD"` | mitigate | Use a section-aware awk scan (not a bare grep) that ignores comment lines (`^\s*#`) and section headers (`^\s*\[`). Acceptance criterion includes `scan_tbd_slots` function name grep. |
| T-05-03 | Repudiation | A post-submission operator runs mainnet-deploy.sh without running preflight first | mitigate | Plan 05-02's mainnet-deploy.sh script's header documents preflight as a prerequisite; Plan 05-05's MAINNET-READINESS.md ≤30-min deploy procedure lists `preflight.sh` as step 1. No code-level enforcement (operator can bypass); risk accepted because operator is a single trusted human (solo build per CLAUDE.md). |
| T-05-04 | Information Disclosure | preflight.sh logs the deploy wallet address or gas balance to CI logs | accept | Only address + balance are logged; both are public on-chain data (every transaction reveals them). No private key or mnemonic ever surfaces. |
| T-05-05 | Denial of Service | Mainnet RPC rate-limits the predict-mainnet-check curl, breaking preflight | mitigate | The probe is a single read-only `sui_getObject` call — well below any public RPC rate limit. preflight invokes it once per run, not in a loop. If the RPC is down, curl's `-fsS` exits non-zero and preflight surfaces the failure; the operator can retry. |
| T-05-06 | Elevation of Privilege | scripts/preflight.sh accidentally executes `sui client publish` or another mainnet-mutating command | mitigate | Plan 05-01 acceptance includes a forbidden-token grep: `! grep -E '(sui client publish\|sui client call.*--gas-budget)' scripts/preflight.sh` (preflight is assert-only). Predict-mainnet-check uses only curl + jq; no sui CLI call. |
| T-05-07 | Information Disclosure | The `PREDICT_MAINNET_CANDIDATE` env var leaks via the Markdown report's "Raw probe output" section | accept | The candidate is a public on-chain object ID — same trust profile as every other contract address in the repo (testnet Predict package ID is hardcoded in `e2e-vault-deploy.sh` L38). No secret content. |

All ASVS L1-applicable threats addressed; mitigations are concrete implementation actions, not generic advice.
</threat_model>
